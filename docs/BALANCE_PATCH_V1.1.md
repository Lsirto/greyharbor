# 平衡补丁 v1.1 实验报告（《灰港三夜》）

> 引擎 v2.4 / AI v2；实验台 `scripts/balance-experiment.mjs`；AI 侧只消费
> `buildView(pov)`，复用 `src/ai/v2/ai.mjs` 的 `chooseAction`，未修改 AI。
> 所有随机走注入式 rng，无 `Math.random`，无外部依赖。

## 1. 前提校正（重要）

背景材料以「AI vs AI 1000 局 P1 胜 842」推断「后手优势约 84%」。实验数据
**不支持这一推断**：

- 第一夜先手由 `randInt(2)` 抛硬币决定，两个座位各约 50% 先手（本实验 600 局中
  先手为 P0 的比例 47.17%，各组一致）。
- P1 的高胜率来自**座位/牌组不对等**（P0=Society、P1=Cult，同一评估型 AI），
  而不是「后手」身份：基线 600 局 P0 胜 100、P1 胜 500（16.67% / 83.33%），
  但按第一夜先手角色分组是先手 335 胜、后手 265 胜（55.83% / 44.17%）。
- 镜像对局（双方都用 Society 预设牌组，400 局）中 P0/P1 胜率 199/200，
  先手胜率 53.0%——座位不对称消失后并无 84% 的后手优势。

因此本次补偿钩子严格按任务定义**只发给第一夜先手方**；它无法修正 P1 座位的
牌组强度差。这一点作为「剩余疑问」保留，不自创规则。

## 2. 实验方法

- 命令：`node scripts/balance-experiment.mjs --games=600 --matrix`
  （单组：`--comp=extraMulligan --value=1`；组合：`--comp=extraMulligan+extraStartingCard --value=1`）。
- 同种子集：所有方案都用 `balance-v1.1-0 … balance-v1.1-599`，AI 决策种子
  统一为 `ai-match-ai:{player}:{seed}`；组间唯一差异是 `firstPlayerCompensation`。
  定稿后脚本对未列出的钩子显式补 0，避免继承引擎新默认值污染对照。
- 统计口径：`firstPlayer` 在**第一夜开始后、第一次行动前**捕获一次；
  `state.firstPlayer` 会在夜 2/3 按「败方先手」轮转，不能用终局值。
- 每步检查 `countCards() === 19`；所有组 `conservation: ok`。

## 4. 方案优劣分析

- **extraMulligan**：先手换牌上限 2→3（+1）或 2→4（+2）。对先手胜率几乎无
  影响（56.00% / 55.33% 对基线 55.83%）；+2 略优于基线，是最接近 50% 的方案，
  且理智结束占比 13.33% 相对基线 14.50% 没有剧烈偏移。副作用是让玩家决策空间
  变大（+2 时每人 163 个换牌动作）。
- **extraStartingCard**：先手第一夜多抽 1/2 张，走现有夜开始抽牌批次
  （`nightStart.draws`），牌堆不足按 §2.4。效果过强且方向错误：先手胜率升到
  64.33% / 68.50%，理智结束占比升到 20.83%（+2），明确淘汰。
- **night1Sanity**：默认起始理智与 `SANITY_MAX` 都是 6，+1/+2 被上限截断，
  在默认规则下是**严格 no-op**（数据与基线逐字段相同）。机制本身在
  `startingSanity < 6` 时有效，已在确定性测试中验证；作为平衡手段不可用。
- **双方案组合**：任务允许单方案不达标时再测组合。本矩阵中 extraMulligan=2
  已是预注册指标下最接近 50% 的单方案，且额外发牌只会把胜率推高，因此未测
  组合（组合只会更远离 50%）。

## 5. 稳健性核对

- 追加同种子集 **3000 局**：基线先手 1635/3000 = 54.50%；
  extraMulligan=1 为 1647/3000 = 54.90%；extraMulligan=2 为 1649/3000 = 54.97%。
  三者都落入 45–55% 区间，理智结束占比 13.7% / 12.93% / 12.87%。
- **逐种子配对**（600 局，基线 vs extraMulligan=2）：先手胜→先手负 31 局，
  先手负→先手胜 28 局，净变化 -3 局；两者都先手胜 304 局，都不胜 237 局。
  说明矩阵里的 0.5pp 差异在抽样噪声范围内，不应解释为真实平衡效果。

## 6. 定稿规则

按预注册指标（600 局矩阵中最接近 50% 且理智结束占比无剧烈偏移）定稿：

> **`options.firstPlayerCompensation = { extraMulligan: 2, extraStartingCard: 0, night1Sanity: 0 }`
> 成为引擎默认值**，不传 options 也生效。只有第一夜抛硬币获胜方换牌上限由 2
> 提到 4；第二/三夜先手轮转按 §2.3 不变；理智与起手牌数不变。显式传参可覆盖。

实测新规则（600 局同种子集，即矩阵 `extraMulligan=2` 行）：**先手胜率 55.33%**，
后手 44.67%，理智结束占比 13.33%，无崩溃、守恒 ok。

理由：三候选中只有 extraMulligan 没有把先手胜率推离 50%（+1 略升、+2 略降），
且 +2 在预注册矩阵中数值最优；理智结束占比未剧烈偏移。更大规模与配对分析显示
效果不显著——这是已知局限，见 §7，未据此自创其他规则。

## 7. 剩余疑问（只记录，不改规则）

1. **84% 的归因**：P1 胜率高是座位/牌组强度差，不是后手优势；本补丁按任务定义
   只补偿抛硬币先手方，因此不会把 P0/P1 胜率拉近 50%（定稿后 P0 仍约 15%）。
   若要修正座位差，需要另一套（未被授权的）规则或牌组调整。
2. **效应量**：600 局与 3000 局的差异均在 ±0.5pp 内，配对净变化仅 -3/600，
   不能证明 extraMulligan 有真实平衡效果；选择依据是预注册指标而非显著性。
3. **night1Sanity 在默认理智 6/6 下恒为 no-op**；若未来起始理智下调，该钩子
   才会生效。是否保留这种「默认无效的选项」待定。
4. **RNG 时点**：为使补偿在换牌前确定目标，第一夜硬币从「夜开始」提前到
   「建立状态、两副牌洗完后」抽取。同一 `randInt(2)`、同一种子下，无换牌洗牌的
   脚本测试硬币值不变；有 AI 换牌的对局随机流顺序会变化，故逐局结果与旧版不同。
5. **夜胜惩罚**：平夜双方 -1 理智、败方 -1 理智延续 v2.1 行为，规则文本 §9.6
   未明写；本补丁未改动，记录同上。
