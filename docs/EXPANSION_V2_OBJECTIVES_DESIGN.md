# 灰港三夜 · 扩展机制设计 v1.4（线索 / 末日双目标）

本文件是 v1.4「双目标」机制的**唯一规则事实源**，与 `GREYHARBOR_RULES_V1.md`、
`EXPANSION_V1_DESIGN.md` 并行：旧规则（三夜两胜、理智翻面、30 卡、三地点、六关键词）
与 v1.3 三机制（动态地点、混沌袋、发掘）全部保留，本文件只做增量。

设计目标：让两个阵营拥有**各自独立、可主动追求的胜利路径**，而不只是战力高低。
学会靠「调查」积累**线索**破案，教团靠「献祭与仪式」积累**末日**召唤旧神；
两条路径都在现有引擎（状态机 + 动作枚举 + 脱敏 view + 效果 DSL）上扩展，不推翻任何旧规则。

纪律（沿用 v1.3）：新机制同步更新 AI 启发式、补测试、跑自对弈与消融，避免"加了玩法 AI 不会用"。

---

## 一、核心规则：两条目标进度条

### 1.1 目标类型由阵营决定

| 阵营 | 目标资源 | 主题 | 胜利文案 |
|---|---|---|---|
| 学会 society | **线索 Clue** | 调查、取证、还原真相 | 真相大白（破案） |
| 教团 cult | **末日 Doom** | 血祭、仪式、召唤旧神 | 旧神降临（召唤） |

- 每个玩家持有一个**只增不减的整数进度** `objective`，初始为 0；其类型由本人阵营推导，
  中立卡不会成为玩家阵营（玩家只能选学会或教团），因此不存在"无目标类型"的玩家。
- 进度对双方公开（不是隐藏信息），双方都能看到彼此距离阈值还差几点，形成竞速。
- 进度本身不消耗卡牌、不改变战力，只在达到阈值时触发胜利。

### 1.2 阈值与立即胜利

- **目标阈值 `OBJECTIVE_THRESHOLD = 7`**（定稿值；初始设计为 5，经阈值扫描与大样本调参，见第五节）。
- 每当进度增加后，若 `objective >= 5`，该玩家**立即获胜**，`reason = 'objective'`，
  并在 result 中携带 `objectiveType`（`clue` / `doom`）。
- 目标胜利可以在**夜中**触发（例如一次献祭正好凑满第 5 点末日），不必等到夜结算。
- **优先级裁定**：若同一动作同时触发"理智归零"与"目标达成"，**理智归零优先**
  （与现有"Sanity zero takes precedence"口径一致）：先判理智归零者负，再判目标。
- 目标胜利与"三夜两胜""理智归零"并列，是第三条比赛胜利路径；三条路径谁先满足谁生效。

### 1.3 机制开关

- `createGame({ mechanics: { objectives: false } })` 可关闭本机制，关闭后行为与 v1.3 完全一致，
  不产生任何 `objective` 字段与事件。默认开启（shipped game）。
- 与 v1.3 的 `anomaly` / `chaosBag` 开关正交，可独立组合，便于消融实验。

## 二、学会 · 线索（Clue）如何获得

学会的线索全部围绕**档案（archive）**这一"调查地点"，鼓励把资源投入档案、争夺档案控制权。

### 2.1 档案入场（可重复）

- 每当一个**己方单位进入档案列且为明放（face-up）**时，获得 **1 线索**。
- 触发路径覆盖正常出牌入场（引擎单位放置点）；从牌堆直接召唤（伊莱亚斯）是教团专属，
  不会产生学会线索。
- 盖牌（face-down）只允许出现在梦境，档案无盖牌单位，因此档案入场即明放，无需处理"翻开"分支。
- 同一单位只在"进入档案"的那一刻触发一次；它在档案中持续停留不会每夜重复给线索。

### 2.2 档案控制（夜结算，每夜至多 1 点）

- 每夜计分后，若学会玩家在**档案列的地点战力严格高于对手的档案列战力**（"赢得档案"），
  获得 **1 线索**。
- 档案战力相等（平）则不给线索；该判定使用夜结算时的 `score.locations.archive`，
  与全局夜胜负相互独立（即使本夜总战力落后，只要档案领先仍可拿线索）。
- 夜结算先于"夜中目标胜利"检查；若这条奖励把线索推到阈值，立即触发目标胜利。

### 2.3 边界裁定

- 一个学会单位若在当夜进入档案，先触发 2.1 的入场线索；夜结算若赢得档案再触发 2.2，
  两者可叠加，不是同一效果。
- 线索只增不减，单位离开档案（被献祭/移除）不回收已获得的线索。
- 异变对档案战力的修正（如"档案低语 +1"）计入档案控制判定，因此学会会偏好档案增益异变。

## 三、教团 · 末日（Doom）如何获得

教团的末日围绕**献祭**与**仪式**，鼓励激进地牺牲己方单位、连打仪式卡，换取召唤加速。

### 3.1 献祭 / 吞噬（可重复）

- 每当一个**己方单位被献祭（sacrifice）或吞噬（devour）**时，获得 **1 末日**。
- 统一在引擎 `_sacrificeUnit` 落点触发（吞噬 `_devour` 内部也调用 `_sacrificeUnit`），
  因此自动覆盖所有来源：
  - 领袖伊莱亚斯的献祭召唤；
  - 掘墓人、降灵会等带献祭的卡牌；
  - 钟爪的吞噬；
  - 效果 DSL 中任何 `sacrifice` 操作。
- 一次献祭只给 1 末日，无论是否带"替代信徒（replacement）"；替代只改变实际被献祭的单位，
  不改变献祭次数。

### 3.2 仪式卡施放（每张 1 点）

- 每当教团玩家打出一张**类型为 `ritual` 的卡牌**时，获得 **1 末日**。
- 当前 `ritual` 类型卡共 2 张：**降灵会 Séance、潮汐仪式 Tide Ritual**。
  （月食 Lunar Eclipse 的类型是 `environment`，不属于仪式，不触发本条。）
- 降灵会本身还会献祭一个单位，因此打出降灵会通常同时获得"献祭 1 点 + 仪式 1 点"共 2 末日，
  这是其作为大型仪式的预期强度，不是重复计数。

### 3.3 边界裁定

- 末日只增不减；被献祭单位进入深渊（abyss）后又被取回，不退还已产生的末日。
- 若献祭因封印/异常等原因未实际执行（没有真正移动单位），不产生末日；
  以 `_sacrificeUnit` 内"单位真正进入深渊"为准，避免空放刷末日。
- 领袖伊莱亚斯从牌堆召唤的单位本身不额外给末日（末日来自其前置的那次献祭）。

## 四、view / 事件暴露（保持脱敏与防作弊）

- 每个玩家的 view 节点新增：
  - `objective`：本人当前进度（整数）；
  - `objectiveType`：`'clue'`（学会）或 `'doom'`（教团）；
  - `objectiveThreshold`：当前阈值（公开常量）。
- 进度是公开信息，对手视角同样可见，不做脱敏；不新增任何手牌/牌堆/盖牌身份信息。
- 新增事件 `objectiveGain`：`{ player, objectiveType, amount, total }`；
  目标胜利仍走既有 `gameOver` 事件，`reason: 'objective'`。
- AI 防作弊审计（源码 import 白名单 + 隐藏信息视角字节一致）需继续通过：
  新字段全部来自 buildView 已公开数据，AI 不直接读引擎状态。

## 五、落地计划（分阶段，测试先行）

### 阶段 A — 数据与状态底座
- 新增 `src/engine/v2/objectives.js`：`OBJECTIVE_THRESHOLD`、`objectiveTypeForFaction()`、
  线索/末日的中英文名与文案（纯数据 + 纯函数，无随机）。
- `normalizeMechanics` 增加 `objectives` 开关（默认 true）；玩家状态初始化 `objective: 0`。

### 阶段 B — 引擎接入 + 测试
- 学会：单位明放进入档案 → 线索；夜结算档案严格领先 → 线索。
- 教团：`_sacrificeUnit` 真正执行 → 末日；打出 `type === 'ritual'` 卡 → 末日。
- 每次增益后做阈值判定（理智归零优先），emit `objectiveGain`，达标走 `_gameOver('objective')`。
- 新增 `tests/v2/objectives-v14.test.mjs`：类型推导、各触发路径、阈值立即胜利、开关关闭回退、
  不重复计数、空放不刷进度、事件字段、牌数守恒、异常不崩溃。

### 阶段 C — AI 更新 + 测试
- `config.mjs` 集中目标权重：阈值、临近阈值的进度递增价值、仪式卡识别、档案/献祭的目标协同。
- `evaluate.mjs`：把双方进度折算进局面分，识别"再走一步即目标胜利"（对应 match win/ loss），
  并在出牌/献祭/仪式/揭示的模拟中同步进度；AI 会主动推进己方目标并警惕对方竞速。
- 保持 view-only 防作弊与隐藏信息测试通过；AI vs AI 大样本 0 崩溃。

### 阶段 D — UI / 动画 / 自对弈验收
- 玩家栏/领袖旁新增目标进度轨：线索用古金、末日用病态青红，进度格 + 增益动画，
  接入现有 fx/audio；结果面板区分"真相大白 / 旧神降临"。
- 浏览器实测各页面一屏不滚动、不溢出；更新 README 与测试计数。

### 平衡方法与验收门槛
- 新增或扩展消融脚本，用 `objectives` 开关对比"开/关"，并记录**目标胜利占比**、
  双向胜率、理智结束占比、夜胜结束占比。
- 阈值调参目标：**目标胜利成为有意义但不主导的结局**（目标占比约 15–30%），
  双向胜率维持 45–55%，且不显著挤压理智结束与夜胜结束的原有结构。
- 全量测试（含新增）全绿；自对弈 1000+ 局 0 崩溃、牌数守恒；若胜率或结局结构漂移，回炉调阈值。

### 平衡裁定（v1.4 定稿）
- 初版阈值 5 在 AI 对弈中导致 **75–86% 的对局由目标结束**，严重挤压夜胜与理智，过度主导。
- `scripts/balance-objectives-sweep.mjs` 对阈值 5–10 各跑 400 局，呈现**明显悬崖**：
  阈值 6 → 目标结束约 62%（仍主导）；**阈值 7 → 约 31%、三类结局均衡**；阈值 8 → 约 5%（机制近乎失效）。
- 定稿阈值 **7**。`scripts/balance-objectives-final.mjs` 用 shipped 默认（阈值 7）跑同种子
  6400 局（含两组座位轮换 + 两镜像），数据固化于 `docs/v14-final-check.json`：
  - 交叉对局：crossAB 53.00/47.00、crossBA 46.95/53.05（均在 45–55%）；先手胜率约 50–52%，无先手优势；
  - 交叉目标结束 **28.5%**、理智结束约 27%、夜胜结束约 44%，三类结局健康共存；
  - 0 崩溃、牌数守恒。镜像不对称（教团镜像理智结束 73.5%、学会镜像目标结束 51%）是
  "教团自损理智 / 学会回血"的阵营固有特征，与 v1.3 记录一致，交叉对局不受影响。
