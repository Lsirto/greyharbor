# 灰港夜谭 · 对局重构与桌面化设计方案

> 范围：在**不新增功能**的前提下，解决"玩不明白、英文乱码、手牌看不清"三大问题，并把游戏做成 **Windows 桌面软件**。
> 已确认方向：**较大重构 + 游戏内全中文 + 桌面端**。

## 一、问题诊断

| # | 现象 | 根因 | 影响 |
|---|------|------|------|
| 1 | "选择翻开效果"弹窗整窗英文，9 个选项文字完全相同 | 引擎给动作生成的是英文调试标签（`engine.js` 写死 `Reveal … (…)`），UI 直接显示；标签未带候选卡中文名 | 看不懂、无法区分候选 |
| 2 | 界面混 `NIGHT/LIVE SCORE/ENVIRONMENT/LEADER/SUBTOTAL/CLUE/DOOM/PASSED/FACE DOWN` 与卡牌英文名 | 模板里写死中英双语标签，卡牌取 `nameEn` | 信息噪音、不专业 |
| 3 | 6 块板、13 个槽位，空槽和数字多，没有视觉焦点 | 每人 3 区域（现场 5 / 档案 5 / 梦境 3）× 双方 | 新手不知道看哪 |
| 4 | 手牌太小、字号小，窗口缩放不自适应 | 固定尺寸、无响应式、底部空间被挤压 | 牌面文字看不清 |
| 5 | 机制一次性堆太多，且无敌方提示 | 三区域 + 双目标 + 异变 + 混沌袋 + 发掘同时出现，缺意图明示 | 核心循环不清晰 |

## 二、设计目标与原则

1. **纯中文**：对局与菜单移除全部英文/技术符号，包括卡牌英文名与装饰英文。
2. **一个清晰核心循环**：看目标与敌方意图 → 选牌/用技能 → 打出并即时反馈 → 结束回合。
3. **单一焦点棋盘**：一屏内只突出当前决策，弱化空槽与无关数字。
4. **桌面优先**：固定桌面窗口与最小尺寸，同时保留网页版（GitHub Pages）。
5. 数据驱动、无 per-id 分支；保持确定性引擎与全量测试可回归。

## 三、新对局设计

### 3.1 核心循环（每回合）

1. 顶部查看**目标进度、当前夜、回合归属、敌方意图**。
2. 底部选择**手牌**（合法位置高亮），或使用**调查员主动技**。
3. 打出 → 播放动画、数值与目标进度即时变化。
4. 点击"结束回合"，交由对方行动。
5. 夜结束：统一翻开结算 → 夜分对比（中文）→ 进入下一夜；先赢 2 夜或达成目标即胜利。

### 3.2 棋盘：从 6 板 13 槽 → 单一对峙线

| 维度 | 现状 | 目标 |
|------|------|------|
| 每人区域数 | 3（现场/档案/梦境） | **1（对峙线）** |
| 每人槽位 | 13（5+5+3） | **6** |
| 双方棋盘总数 | 6 | **2** |
| 单位放置 | 受卡牌 `location` 限制 | 任意单位可放入任意空槽 |
| 视觉焦点 | 分散、空槽多 | 只高亮当前可操作位置 |

> 关键节奏决策（见第六节）：因单位当前**跨夜持续累积**，6 槽单线会溢出。建议改为**每夜自成一局、夜结束清空单位**（目标/理智/夜胜场跨夜保留），使每夜都是干净、可读的独立交锋，契合参考游戏"单一清晰循环"。

### 3.3 卡牌类型归位（数据驱动，统一规则）

| 类型 | 数量 | 新归属 |
|------|------|--------|
| 单位 unit / 古神 oldgod | 18 | 对峙线空槽 |
| 领袖 leader | 6 | 左侧调查员区（不入对峙线） |
| 地点 location | 2 | 单个"据点"槽；新据点替换旧据点（旧的进弃牌堆） |
| 环境 environment | 2 | 顶部"环境/天气"条，夜结束自动清除 |
| 装备 equipment | 1 | 挂载到指定单位（不占槽） |
| 事件 event / 仪式 ritual | 5 | 一次性效果，结算后立即进弃牌堆（不占槽） |

### 3.4 调查员（领袖）区

- 左侧突出立绘、姓名、**理智槽**与主动技按钮；主动技每夜可用一次，用后置灰并显示"今夜已使用"。
- 皮肤换装在此区域同样生效（沿用已有皮肤链路）。

### 3.5 目标条与胜负

- 顶部一条进度条：当前值 / 阈值，按阵营显示"线索"或"末日"，并附一句中文胜利条件。
- 三条胜利路径并存：① 先赢 2 夜；② 目标累计达阈值；③ 对方理智归零。平局按 夜胜场 → 目标进度 → 总分 依次判定。

### 3.6 敌方意图（借鉴《杀戮尖塔》《Into the Breach》）

- 人机对战时，在对方调查员/对峙线上显示意图标签，如"准备使用主动技""倾向强化单位""打算过牌"。
- 由 AI 已选动作推导，纯展示、不改变规则；**人人对战不显示**（不泄露真人信息）。

### 3.7 手牌与中文提示

- 底部手牌整体放大、固定可读字号；悬停抬起并放大，选中态高亮，合法落点发光。
- 关键词（隐秘/封印/连锁/理智反噬/腐化/献祭）悬停显示**中文解释气泡**；卡面只显示中文卡名与效果。

### 3.8 理智与混沌袋

- 理智在调查员区以清晰槽位显示（0–6），并标注"理智/疯狂"状态。
- 触发混沌袋检定时弹出居中中文弹窗：抽取动画后显示 **大成功 / 成功 / 失败**、数值修正与一句白话解释，不再出现原始符号。

## 四、机制重新归位

| 机制 | 现状 | 新处理 |
|------|------|--------|
| 连锁 chain | 分"档案内其他"/"相邻" | 统一为对峙线"相邻"或"己方其他单位"，单线仍成立 |
| 光环 aura | 含 `scope.location` | 改为 己方/全体 + 卡牌类型 维度，移除区域维度 |
| 异变 anomaly | 绑定区域 | 改为影响整条对峙线的事件，顶部横幅展示 |
| 隐秘 stealth | 可入梦境暗放 | 仍可在对峙线盖牌暗放，取消独立梦境区 |
| 评分 | 分区域小计 + 总分 | 只保留总分；夜胜负按总分对比 |

## 五、桌面端方案（Electron）

- 已验证：npm 已用国内镜像，Electron 最新 45.5.0、二进制镜像可达，安装可行。
- 选型理由：现有工程是纯静态 ES 模块 + import map，浏览器经 HTTP 拉取卡表（`file://` 下模块与 fetch 受限）。Electron 可直接复用，无需 Rust 工具链。
- 加载方式：主进程内置**零依赖静态服务器**（Node `http`，监听 127.0.0.1 随机端口），窗口加载 `http://127.0.0.1:<port>/app.html`，规避 `file://` 限制。
- 窗口：最小尺寸 1280×800、应用图标、移除默认菜单栏、单实例。
- 目录：新增 `desktop/`（主进程 `main.cjs`、图标）；`electron`/`electron-builder` 仅作开发依赖，网页运行仍零依赖；`node_modules/`、`dist/` 加入 `.gitignore`。
- 打包：`electron-builder` 产出 NSIS 安装包（.exe，可选便携版）。

## 六、待确认的关键参数

1. **夜节奏**（推荐 A）：
   - A. 每夜独立交锋、夜结束清空单位（6 槽单线成立，最清晰，改动较大）。
   - B. 保留单位跨夜累积，单线扩到约 10 槽（改动小，但单线偏长、信息仍多）。
2. **对峙线槽位**：建议 6（A 方案下）；若选 B 则约 10。
3. **敌方意图**：建议仅人机显示、人人隐藏。
4. 窗口最小尺寸是否采用 1280×800。

## 八、参考借鉴

- Ripley's Jelly Camp（抖音 HOYOMAX）：单一核心循环、大字易读、即时反馈；评论区借鉴"深空当铺 + 天国拯救 2 炼金"。
- 《杀戮尖塔》：敌方意图、单场聚焦、强引导。
- 《Into the Breach》：完美信息、意图明示、小而清晰的交锋。
- 《炉石传说》：单一战场、大卡、关键词提示。
- 《暗黑地牢》：克苏鲁氛围与压力/理智呈现。
